# 🏛️ Project Governance

## Project scope

Chota Bheem Adventures is a small static browser game. Project governance is intentionally lightweight. There is no foundation, steering committee, paid support organization, or formal release board.

## Maintainer

The repository is maintained by Brajesh Kumar through the GitHub account [@Brajesh31](https://github.com/Brajesh31). Repository permissions and GitHub branch protection settings determine who can merge or publish changes.

## How decisions are made

- Small bug fixes and documentation improvements can be proposed through pull requests.
- New gameplay features should start with an issue describing the player problem and expected behavior.
- Changes that affect controls, scoring, assets, accessibility, privacy, or deployment must update the relevant documentation.
- Asset contributions require clear redistribution rights and attribution before merge.
- Security concerns should be reported privately as described in [SECURITY.md](SECURITY.md).

## Review expectations

A review should consider correctness, maintainability, accessibility, browser compatibility, performance, privacy, security, and licensing. Pull requests should identify which checks were run and which remain untested.

## Releases

There is no fixed release cadence or promised support window. Static releases should follow [docs/release-process.md](docs/release-process.md) and update [CHANGELOG.md](CHANGELOG.md).

## Changes to this policy

The maintainer may update this document as the contributor base or project scope changes. Material governance changes should be recorded in the changelog.
